## Definition

Jason's Double Onion is a receipt-gated audit kernel for investigating one disputed event, claim, decision, or consequence through two independent evidence onions and in both temporal directions.

The center is the disputed object:

```text
DISPUTED EVENT / CLAIM / CONSEQUENCE
```

### Onion A — Reality / Record

```text
CLAIM / EVENT
→ ARTIFACT
→ PRIMARY OR COMPETENT SOURCE
→ VERSION / ARCHIVE
→ TIME + PLACE
→ SPEAKER / WITNESS / OBSERVATION
→ HUMAN OR RECORD CONSEQUENCE
→ CONTRADICTORY RECORD IF ANY
→ RECEIPT
```

Onion A asks: **What does the record establish happened, changed, appeared, disappeared, or was observed?**

### Onion B — Authority / System

```text
PERSON / INSTITUTION / SYSTEM
→ ROLE / JURISDICTION
→ AUTHORITY / DELEGATION
→ POLICY / RULE / MACHINE RULE
→ EXECUTION IDENTITY / PERMISSION
→ ACTION
→ RECORD DELTA
→ CONSEQUENCE
→ NOTICE / REASON
→ REVIEW / CORRECTION
→ RECEIPT
```

Onion B asks: **Who or what had authority to act, what rule governed the action, what actually executed, and what correction path exists?**

## Two Directions

Each onion may be replayed forward or reverse:

```text
FORWARD: ORIGIN → ACTION → CONSEQUENCE
REVERSE: CONSEQUENCE → ACTION → ORIGIN
```

Architectural synthesis:

```text
2 ONIONS × 2 DIRECTIONS = 4 TRACES
```

This equation is a synthesis of the lineage experiments, not a claim that every predecessor repository quoted the equation verbatim.

## Crossing Rule

The onions remain independent until a receipt binds an edge between them.

```text
PUBLIC_RECORD != INFRASTRUCTURE_CAUSE
LOGIN != OWNER
OWNER_ROLE != ACTION
HASH != SEMANTIC_TRUTH
OFFICIAL_SOURCE != AUTOMATIC_AUTHORITY
REPLAY_SUCCESS != TRUTH
```

No person, login, cloud provider, editor, deployment actor, motive, authority, or causal relationship may cross from one onion into the other merely because the two narratives look compatible.

```text
CROSS_ONION_EDGE_REQUIRES_RECEIPT = TRUE
```

## Burden Breakthrough — Audit Rule

When an institution imposes or maintains an individual consequence, the Double Onion audit does not treat repeated individual re-proof as reconciliation of the institution's own record.

```text
INDIVIDUAL CONSEQUENCE
→ INSTITUTIONAL CLAIM / RULE / DECISION
→ REQUIRE INSTITUTION-SIDE RECEIPTS FOR:
   AUTHORITY
   ACTION
   EXECUTION IDENTITY WHEN MATERIAL
   REASON / NOTICE
   RECORD STATE
   REVIEW / CORRECTION
→ REPLAY
```

Core invariant:

```text
REPEATED_CITIZEN_REPROOF != GOVERNMENT_RECORD_RECONCILED
```

This is an **audit-sufficiency rule**, not a universal statement that every legal burden of proof always belongs to an institution. Applicable legal burdens remain controlled by the governing Constitution, statute, rule, contract, tribunal, or other competent authority.

## Terminal States

```text
PASS
HOLD
CONFLICT
REJECT
```

- `PASS` — the bounded proposition reconciles through independently replayable receipts.
- `HOLD` — a required source, authority, action, identity, reason, correction, or receipt is absent.
- `CONFLICT` — valid bound records disagree; disagreement is preserved rather than forced closed.
- `REJECT` — the proposed proposition is contradicted by the bound evidence or violates the evidence membrane.
